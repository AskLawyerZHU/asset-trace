# 渠道卡：企查查 MCP（qcc-company）

A 层第二主力，与元典互补。**企查查强在"执行/涉诉时间线+金额"，元典强在"文书全文+法条"**。两个都连上时先跑企查查风险扫描分诊，再按命中维度下钻。

## 推荐调用顺序

1. `get_company_by_query`（名称→锁定 USCC，多候选必须交用户选定）
2. `get_company_risk_scan`（**35 项风险因子一次性分诊**，返回各维度命中数）→ 只对命中维度下钻，省调用
3. 按命中下钻明细（下表映射）
4. 与元典结果交叉，冲突标 ❗

## 工具映射（按 35 因子）

| 查询目标 | 工具 | 实战要点 |
|---|---|---|
| 风险总分诊 | get_company_risk_scan | 先跑它；0 项≠无风险，须补舆情 |
| 终本案件 | get_terminated_cases | **给执行标的+未履行金额**→可算出已履行部分；一条即可看清全部终本与金额 |
| 限制高消费 | get_high_consumption_restriction | **申请人字段=竞争债权人清单**，直接可用 |
| 立案信息 | get_case_filing_info | 给当事人角色（原告/被告/上诉人）→ 一眼判断债权面还是负债面 |
| 裁判文书 | get_judicial_documents | 给案件金额+裁判结果摘要，比元典列表信息密度高 |
| 开庭公告 | get_hearing_notice | 给案号+当事人+开庭时间，可还原诉讼时间线 |

## 任职锚定法（自然人机器可查主路径，v1.2）

自然人被执行人没有直接查询入口，但企查查全部 `get_executive_*` 工具（18 维：失信、被执行、终本、**限高、限出境**、裁判文书、股权冻结/出质、终本、税收违法、司法拍卖询价、被控制企业、相关企业等）都支持「企业名称 + personName」双锚定。**锚点不难找，难在知道要滚雪球**：

**第一步·找锚点公司**（按成本从低到高）：
1. 案卷内已知公司（追加股东/董监高场景，被执行人是该公司股东）→ 直接用；
2. `get_key_personnel` / `get_company_registration_info`：已知公司的董监高、历史法代名单；
3. 裁判文书"本院查明"部分记载的任职（法定代表人/股东/高管）——文书深挖产出；
4. 社会组织、私募登记（见 10 卡）。

**第二步·18 维分诊**：对每个（锚点公司, 姓名）对调 `get_executive_risk_scan`，返回 18 项风险维度命中数。纪律：scan 只分诊，**未下钻对应原子工具前禁止凭计数定性**。

**第三步·命中下钻**：只对命中维度调原子工具（失信→`get_executive_dishonest`，被执行→`get_executive_judgment_debtor`，限出境→`get_executive_exit_restriction`，终本→`get_executive_terminated_cases`……18 维一一对应）。

**第四步·滚雪球扩锚点**（关键增量）：
- `get_executive_controlled_companies` / `get_executive_related_companies` / `get_executive_investments`：从一家已知公司滚出他控制/关联/投资的其他公司；
- `get_executive_legal_rep_roles` / `get_executive_positions`：任职与法代履历；
- 每发现一家新公司 → 回到第二步用新锚点重跑（不同锚点覆盖的数据库切片不同）。

**第五步·穷尽判定**：全部锚点跑完仍未命中 → 自然人 A 层穷尽，退回执行网四库人工 + 文书库甄别，核对表 N5/N6/N7 标 ⏳（原因：无任职锚点/执行网验证码），禁止标"无记录"。

**双重纪律**：①任职锚定前仍须过 N1 同名甄别——锚点公司里的同名同姓不是本人；②"查不到任职"≠"无任职"（企查查覆盖限制），N8 只能写"企查查口径 0 任职"。

## 财产与经营专项接口（★v1.6 实测补录，映射 E13–E17）

| 扩展线 | 工具 | 实战要点 |
|---|---|---|
| E13 动产抵押 | get_chattel_mortgage_info | 抵押权人=潜在优先债权人；**吊销/停业企业必再查历史版**（已解除抵押=处置过设备的痕迹） |
| E13 历史 | get_historical_chattel_mortgage | ⚠️ 2026-10-31 实测：工具描述中提及但**当前环境未注册**——未注册时该线标 ⏳（原因：接口缺失），走中登网人工补，禁止标"无记录" |
| E14 融资租赁 | get_financing_lease_info | 出租人视角可反查其客户；租赁设备=出租人取回权资产（设备密集型企业重点） |
| E15 土地 | get_land_grant_info（+land_mortgage_info / land_transfer_info） | 命中即 P1；土地位置/面积/成交价直接进线索池 |
| E16 财务数据 | get_financial_data | **AI 数据纪律**：净利率/资产负债率/营收同比等为服务端精算字段，**逐字引用，禁止用原始数自行重算**；无披露记录的中小企业/吊销企业返回"无记录"=有效闭合 |
| E17 招聘 | get_recruitment_info | T+0；招聘清零=停业信号（与年报从业人数、社保人数交叉） |
| E4 招投标 | get_bidding_info | 支持 role 过滤（中标方/招采方/投标方/代理方/被提及）+ date_from 日期过滤——查对外债权用 role=中标方，查应付债务用 role=招采方 |

**输出形态注意**：此类工具部分返回结论化文本（如"未发现任何记录""当前无记录"）——这是**有效闭合证据**，核对表照标 ✅（来源+查询日）；与返回明细列表的工具同等对待。

## 实测发现的边界（2026-10-22 两案实测，v1.2 修订）

1. **无自然人被执行人入口，但有锚定路径（v1.6.1 限定范围）**：企查查全部工具以企业为主体，不能按姓名直接查自然人；**"任职/持股"一条线靠任职锚定法（见上节）**。⚠️ 但自然人的**涉诉史、执行史、终本、刑事记录、对外债权不是本卡职责**——元典案例文书库按姓名即可直查，且实测是主力源（2026-10-29/30 两自然人报告：金根宝核对表 12 行中 6 行 ✅ 来自元典、仅 1 行来自企查查）。企查查在自然人场景的实测定位：金根宝（无任何任职）锚定法穷尽为 ⏳，属预期降级；有任职的自然人（如公司股东、法代）可一次扫描 18 维。
2. **立案/文书有滞后**：实测 2025 年新立案的追加案未进"立案信息"与"裁判文书"（裁判文书停留在 2023 年），只在**开庭公告/法院公告**里出现 → 时间线必须三表合看（立案+开庭+公告）。
3. **风险扫描 0 项字段勿当无风险**：未含舆情，且历史已移出记录在 historical 系列里。
4. 金额口径：终本给"执行标的/未履行"，两者差额=已履行部分，报告里要写清楚，别把标的全额当未受偿。
5. 调用成本：一次 scan + 按命中下钻，避免 35 个工具全跑。

## 自然人检索三源三层分工（★v1.6.1 实测修正，覆盖旧表述"自然人只能靠企查查"）

| 层 | 源 | 覆盖的核对表行 | 路径 |
|---|---|---|---|
| 第一层·主力 | **元典案例文书库** | N1 甄别、N2 文书、N3/N4 执行史与终本（裁定全文）、N9 对外债权、刑事与服刑记录 | **按姓名直查**（keywords=姓名），无需任何企业锚点；实测 12 行核对表贡献 6 行 ✅ |
| 第二层·任职单线 | **企查查** | N8 任职与持股、N7 限出境（依赖 N8） | 仅两条路：①姓名关键词模糊命中（噪声大，实测 78:1）；②企业名+姓名双锚定下钻（无任职则整线关闭） |
| 第三层·在册状态 | **执行网人工核** | N5 失信、N6 限高、N3/N4 在册状态 | 两 MCP 均**无自然人名单库**，执行网四库是唯一权威源（解维冬案 4 行即人工核回填解锁） |

**执行顺序**：元典文书库先行甄别锁定身份（N1）→ 企查查任职锚定（N8，且必须在 N1 锁定后进行）→ 执行网人工核回填在册状态。禁止跳过第一层直接拿姓名裸查企查查。
